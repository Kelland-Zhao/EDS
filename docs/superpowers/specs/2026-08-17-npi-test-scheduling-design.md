# NPI 测试排期（Phase 2A）— 设计文档

> **Phase 2 第一个迭代：排期页 + 状态流转 + 草稿表一次性导入。**
> 承接设计文档《2026-07-24 NPI 新品测试管理》Phase 2 规划，按 2026-08-17 需求讨论收敛范围。

**Goal:** 让测试组在 NPI 系统内完成测试任务的排期与状态管理，摆脱草稿表（2026 Test Plan）多人编辑、状态混乱的现状。过渡期与草稿表并行运行，不双向同步。

**架构:** GAS Web App 单体架构，新增 1 个页面（NPI_Dashboard），复用 Code.js 后端与 NPI_TestTasks 数据表，无新数据表。

---

## 业务决策（2026-08-17 需求讨论结论）

| # | 议题 | 结论 |
|---|------|------|
| 1 | 与 2026 Test Plan 草稿表关系 | **并行过渡期**：NPI 排期页用自有数据先跑起来，与草稿表互不同步；观察使用后决定迁移 |
| 2 | 角色与权限 | **过渡期测试组闭环**：测试组自己建、自己确认、自己执行；计划部审批留待 2B |
| 3 | 状态流 | **五态 + 已取消**：待确认 → 已排期 → 执行中 → 已完成；任意未完成状态可取消。「已评审」归 Phase 4 |
| 4 | 机台状态 | **冲突提示**：同机台同天多条未完成任务标黄提示，人工判断；不做甘特图 |
| 5 | 主视图 | **周列表视图**：周筛选/分组 + 状态/机台/发起人/来源筛选，DataTables 实现 |
| 6 | 紧急插入 | **仅标记+高亮**：来源选「紧急」→ 红色高亮置顶，无额外流程 |
| 7 | 草稿表导入 | **一次性手动导入**（见下节），不做同步 |

## 状态机

```
待确认 ──「置已排期」──→ 已排期 ──「开始执行」──→ 执行中 ──「完成」──→ 已完成
   │                        │                        │
   └──────────「取消」（任意未完成状态）──────────────→ 已取消
```

- 每个状态迁移有对应行内操作按钮；非法跳转由后端拒绝（如已完成不能再取消）
- 状态写入 NPI_TestTasks 第 3 列（现有列，无表结构变更）
- 已转正的工艺记录不阻止任务状态流转（状态与工艺卡生命周期解耦）

## 页面：NPI_Dashboard（测试排期 / Test Scheduling）

**路由:** `?v=NPI_Dashboard`；导航「测试计划」按钮启用（替换 Coming Soon）。

**页面结构:**

```
┌─ NavBar：测试计划 / Test Scheduling ───────────────┐
┌─ 工具栏 ──────────────────────────────────────────┐
│ [周选择器 WKxx ▾] [状态筛选 ▾] [机台筛选 ▾]         │
│ [来源筛选 ▾] [发起人筛选 ▾]                        │
│ [新建任务] [从测试计划导入]                         │
└────────────────────────────────────────────────────┘
┌─ 任务列表（按周分组，紧急置顶）─────────────────────┐
│ 任务号 | 产品 | 模具 | 机台(机型) | SKU | 物料 |     │
│ 状态徽章 | 计划日期 | 负责人 | 操作按钮             │
└────────────────────────────────────────────────────┘
```

**列与行为:**
- 任务号 / 产品名称 / 模具编号 / 机台编号(机型) / 适用SKU / 物料 / 状态徽章（中英双语，不同状态不同颜色）/ 计划日期 / 负责人 / 操作
- 紧急任务（来源=紧急）：行背景红色高亮 + 置于本周分组顶部
- 冲突提示：同一机台 + 同一计划日期存在 ≥2 条「待确认/已排期/执行中」任务 → 该行机台单元格黄色警示 + 悬浮提示列出冲突任务号
- 操作按钮按状态显示：
  - 待确认 → [置已排期] [取消]
  - 已排期 → [开始执行] [取消]
  - 执行中 → [完成] [取消]
  - 已完成 / 已取消 → 无操作
- 点击任务行 → 跳转 `?v=NPI_ProcessRecord&taskID=xxx`（工艺参数页自动选中该任务）
- [新建任务] → 跳转 `?v=NPI_ProcessRecord&new=1`（自动打开新建弹窗）

**周选择器:** 由任务计划日期动态汇总出周列表（如 WK33 2026/8/14~8/20），默认当前周；筛选器联动。

**数据加载:** 复用 `loadNPITestTaskList`（已含全部所需字段），前端分组/筛选/冲突检测。数据量小（百级），全量加载无压力。

## 草稿表导入（一次性、手动触发）

**数据源:** 2026 Test Plan 表（`17ys3UDFWjhfaPnk0TErqqeU0FnMP7nsRoRsTmlmm2fg`）`注塑测试` 工作表（仅 IM 工序；植毛测试与 TF 支持一起后做）。

**交互:**
1. 工具栏 [从测试计划导入] → 弹窗列出草稿表全部数据行（含已完成/取消行，供用户选择）
2. 已导入行（见去重）置灰并标记「已导入」；默认全部不勾选，手动勾选要导入的行（2026-08-20 变更：避免一键误导入大量行）
3. 勾选 → [导入] → 批量创建任务 → 结果提示（成功 N 条 / 跳过已导入 M 条）

**字段映射:**

| 草稿表（注塑测试） | NPI 任务 | 说明 |
|---|---|---|
| 日期 | 计划日期 planDate | |
| 产品名称 | 产品名称 productName | |
| 模具号 | 模具编号 moldNo | |
| 测试机台 | 机台编号 machineNo | 机型 machineModel 由 Workcenter 表自动带出 |
| 测试说明 | 备注 remark | |
| 完成状态 | 状态 status | 按下方映射表 |
| — | 发起人 reqPerson | 导入人（当前登录用户 姓名\|工号） |
| — | 来源 source | 周计划 Weekly |
| — | 工序 processType | IM |
| — | SKU / 物料 | 留空，导入后在任务编辑中用 BOM 联动补齐 |

**状态映射:**

| 草稿表状态 | NPI 状态 |
|---|---|
| 已完成 | 已完成 |
| 正在进行 | 执行中 |
| 延期 | 已排期 |
| 未完成 | 已排期 |
| 满产 | 待确认 |
| 模具不在线 | 待确认 |
| 取消 | 已取消 |

**去重:** 以「产品名称 + 模具号 + 机台 + 日期」四元组匹配 NPI_TestTasks 已有任务；完全相同的组合视为已导入，跳过并计数提示。不写来源标识列（并行过渡期不做双向对账）。

## 验证清单

1. 导航进入测试排期页，默认当前周，任务列表按周分组、紧急置顶
2. 状态流转：待确认→已排期→执行中→已完成，每步行内按钮正确出现；非法跳转被拒绝（如直接调已完成→取消报错）
3. 取消：待确认/已排期/执行中 均可取消；已完成无取消按钮
4. 冲突提示：给同一机台同一天建 2 条未完成任务 → 两行均标黄；完成其中一条后警示消失
5. 紧急任务：来源=紧急 → 红色高亮置顶
6. 从测试计划导入：弹窗列出草稿表行；勾选导入后 NPI 任务表出现对应任务（状态按映射表）；再次打开导入弹窗，已导入行置灰
7. 四元组去重：同产品+模具+机台+日期再次导入 → 跳过并提示条数
8. 工艺参数页联动：排期页点击任务 → 工艺参数页自动选中；new=1 → 自动打开新建弹窗
9. 草稿表不可访问时，导入弹窗给出错误提示，页面其他功能正常

## 实现变更记录（2026-08-21，实现后同步）

以下变更已在实现/测试过程中落地，本文档上方各章节保留原始设计决策（历史记录），以本表为准：

| # | 变更 | 原设计 | 现实现 | 原因 |
|---|---|---|---|---|
| 1 | 新建任务按钮 | 跳转工艺参数页 + `new=1` 自动弹窗 | **就地弹窗**（共享组件 `NPI_TaskModal.html` / `NPI_TaskModal-js.html`，两页共用；`onTaskSaved(tid)` 页面钩子） | 用户要求「与工艺参数页新建按钮功能完全一致」 |
| 2 | 草稿表导入 | 批量勾选导入（`importTestPlanRows`） | **单条导入**：行内「导入」按钮 → 弹窗预填 → 标准创建路径（`createNPITestTask` 支持 `initialStatus` 五态白名单，导入一步到位）；批量函数与路由已删除 | 用户要求取消批量，保证每条走完整校验（BOM 联动/物料/协作人） |
| 3 | 导入默认勾选 | 默认勾选未导入行（8/20 改为不勾选） | 无勾选框（单条按钮） | 随变更 #2 |
| 4 | 协作人字段 | 无 | `NPI_TestTasks` 第 22 列；弹窗多选（`getUseID` 数据源，存储 `姓名\|工号`）；任务安排四页面（任务列表/今日看板/我的任务/资源甘特）经 `loadAllNPITasks` 桥接只读展示，早会日报收件人自动纳入 | 协作测试人员在任务安排侧看不到任务（桥接原硬编码 `collaborators: []`） |
| 5 | 预计完成日期 | 无（dueDate 等同计划日期） | `NPI_TestTasks` 第 23 列，**必填**；桥接 `dueDate`（空回退计划日期）；排期页新增「计划完成」列 | 与任务安排「截止日期」对齐，超期口径一致 |
| 6 | 状态映射 | 本 spec「状态映射」表 | 实装于 `mapNPIStatusToEDS_`（待确认→等待中/已排期→未开始/执行中→进行中/已完成→已完成/已取消→已取消）；任务安排侧五入口复用 | 任务安排侧已有桥接 |
| 7 | 页面标题 | 测试排期 / Test Scheduling | 导航与页面标题改「测试计划 / Test Scheduling」 | 用户定名 |
| 8 | 任务列表加载 | DataTables | 原生 Bootstrap 表格 + 周分组行（自定义分组/置顶/高亮更直接） | 实现取舍 |
| 9 | 验证清单第 6/7 条 | 批量导入相关 | 以单条导入流程为准（行内导入 → 预填弹窗 → 保存 → 置灰；四元组去重保留） | 随变更 #2 |

**新增 UI 修正（测试期）**：物料 Select2 加 `selectOnClose`（输入文本关闭下拉时提交，避免「看似已填实则丢弃」）；资源甘特越窗任务条跳过（结束日早于窗口起点/开始日晚于窗口末尾不渲染）；截止日期读取加 Date 对象防护（统一 `yyyy-MM-dd`）。
