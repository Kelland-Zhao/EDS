# EDS 自动任务监控设计

1. **目标与架构**  
   在 EDS 新增“系统工具 → 自动任务监控”，供 Kelland 查看 ScheduledTask 的任务计划及日志。采用 EDS 集成方案，复用现有导航、路由及 UI；ScheduledTask 继续负责执行任务。

2. **数据来源**  
   只读“定时运行配置文件”的「定时设置」「菜单设置」和 `Log`。定时设置及菜单设置的第2行为表头，Log 第1行为表头。按已核实的完整字段名建立映射；缺失或重复字段时停止读取并显示配置错误。任务按函数名区分，包装函数不自动合并。

3. **个人访问限制**  
   页面入口与数据接口均在后台检查真实访问者邮箱，仅允许 `kelland_zhao@colpal.com`。身份为空或不匹配时拒绝访问，不用前端姓名、工号、邮箱或脚本执行者身份兜底。新增 `userinfo.email` scope；EDS 现有公司域访问及执行身份保持不变。上线时验证真实访问者身份是否可用。

4. **展示与交互**  
   提供任务概览、异常与待核实、日志历史三个视图。展示任务名称、函数、计划、下次计划、最近日志及详情。支持搜索、状态和最近1／7／30天筛选，默认7天。每60秒刷新，可手动刷新，页面隐藏时暂停刷新。沿用 EDS 的 UI、logo 和双语格式。

5. **状态与计算逻辑**  
   四项概览为任务数、今日有日志的任务数、今日失败／异常日志条数、今日到期未见定时日志次数。仅原始状态“失败”“异常”计入失败／异常条数；“警告”单独标注。“超期N天”“到期当天”“提前N天”作为业务提醒保留。成功日志不等同于整次执行完成，不计算成功率，不推断运行中或统一耗时。历史错误不会被后续成功日志隐藏。

6. **计划判断**  
   使用来源表时区，沿用现有月、星期、当月周次、日及多时间点的交集规则；严格验证时间值。未来366天内搜索下次计划，无匹配则明确显示。今日计划过去15分钟后，若该计划至下一同函数计划之间未见定时日志，标记“到期未见日志，待核实”。手动日志不抵消提示；无自动计划的任务不参与判断。缺少执行编号导致的延迟关联不确定性明确注明，不断言漏跑。

7. **读取完整性与错误处理**  
   每次按固定源行上界最多读取最近20,000行日志，显示实际覆盖范围和更新时间。超限、时间无法解析或读取期间边界变化时标记覆盖不足，停止缺日志判断；边界变化可重试一次。普通读取失败时保留旧数据并标记过期；无权限时清空数据。日志内容转义后展示，缓存使用前必须先校验身份。

8. **修改范围与验收**  
   新增看板后端、页面、页面逻辑和测试；修改 EDS 路由、导航入口及所需 scope。源业务表、定时设置、日志、ScheduledTask 任务及调度均保持只读，不增加重跑、修改计划或消息发送功能。先完成本地实现和测试，不推送或发布；真实数据和个人访问限制的线上验证另行报告。
